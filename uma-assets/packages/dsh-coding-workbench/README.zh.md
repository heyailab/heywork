# @deepseek-ai/dsh-coding-workbench

[English](README.md) | 中文

## 概述

管理工作区内的命令执行记录、版本化验收标准、关联源码的问题、保留的改动和隔离开发任务。应用组合统一挂载服务，并在标准、PTC 与 Uma 预设中提供工具。桌面交付验证读取同一服务，不需要另装 UmaDev 或 super-dev 运行时。

## 使用

默认导出是服务类。程序化配置验证使用其静态 `Config` schema，入口的具名 `Config` 导出仅为类型。

`startCheck` 可选接收 `expectedArgv`；提供时，接收执行阶段会与发现的命令比较，在记录或执行检查前拒绝已变更的参数。此比较验证命令调用参数，不保证脚本内容不可变。

<a id="use"></a>

Web/桌面组合提供服务及其文件系统、子进程、沙箱、存储、会话与 worktree 依赖。预设在普通开发工具旁挂载 `/tools` 消费者、强制“编辑后验证”的 `/policy` 消费者，以及注册基于证据的完成指引的 `/protocol` 消费者。每个消费者均提供独立的运行入口；包中包含这些入口依赖的所有生成的共享 JavaScript 分块。部署限制由 [Config](src/config.ts) 校验，项目检查 argv 与可选的按检查覆盖 glob 来自支持的清单或 `.hey/coding.json`；发现检查不会执行命令或安装依赖。

HEY 编码配置使用 `advise`：创建项目骨架和多文件修复可以连续进行，无需每写一个文件就先通过检查。待验证义务和失败证据仍保留，只有真实通过的检查才能清除符合条件的义务。部署方可显式选择 `enforce`，要求严格的编辑与检查交替。

`/standards-context` 在每次请求前读取当前执行目录的已知项目清单，以哈希记录来源，按实际出现的语言与框架选择共享规范。它不读取任意清单字段给模型，不执行脚本，不把选型当作验证；单体仓库需继续核对目标子包。`fileBytes` 和 `contextBytes` 是可配置的元数据读取与完整上下文上限，失败或超限会明确提示改用显式检查。选定规范通过既有运行时上下文进入 Session 日志，卸载取消并等待准备操作。 自动准备包含所选指南全文，`guideLanguage` 可选择 `en` 或 `zh`，默认 `en`。`coding_inspect` 的标准模式可用 `guideId` 和 `contentLanguage` 读取一篇适用指南，不需要先手动导入知识库。 运行文件清单包含 `lib/standards-context.js` 及其 `lib/source-*.js`、`lib/process-*.js` 分块；工作区检查会拒绝缺少其中任一项的配置。

编辑后验证策略（`coding-edit-policy`，模式 `off` / `advise` / `enforce`）按会话跟踪 `write`、`edit`、`apply_patch` 改动的文件：`advise` 在每次编辑结果上附加提醒；`enforce` 进一步要求下一次修改前先取得新的检查反馈。完整、源码前后一致且已结算的失败检查，允许继续修复它之前的编辑，但不清除待验证义务，也不代表验收通过；只有通过的检查才能解除符合条件的待验证编辑。更晚或仍在进行的编辑不能借用该失败检查。读取或取消历史检查、跳过全部检查、源码扫描不完整都不能解除待验证编辑。发现、读取与 `coding_check` 本身始终放行。

原生与 PTC 工具事件让验证义务在策略替换、Host 重启、会话恢复与分叉后继续保留，也包括策略卸载或关闭期间记录的编辑。失败或中断的修改仍需验证，除非结果能证明分派尚未开始。通过的检查只解除其开始前已经结算的编辑；更晚或仍在执行的编辑继续待验证。紧凑的结果元数据在命令输出转存后保留检查证据。

`coding_inspect` 的 `mode: "standards"` 搭配显式 `languages`，选择共享的有来源规范目录。结果包括条件化规则、官方出处、指南身份与实际发现的项目检查名称，并明确标为 `verification: "not-run"`。14 篇原创双语指南和 23 条规则引用 12 组官方来源，不打包公司手册。仓库现有约定优先于不兼容的风格偏好，选择规范不代表合规通过；需把适用检查关联验收并实际执行，无法机检的规则另留评审证据。

`coding_check` 支持 `scope: "changed"`：路径相对于所选工作区或任务目录，不包含仓库中的同级目录；覆盖 glob 选择受影响检查，未声明覆盖的检查始终运行，变更列表不完整时运行全部检查。空变更集跳过全部检查，待验证编辑仍需验证。

`/tools` 的能力模式默认是 `full`，保留完整实现工具。`coordinate` 允许读取证据、记录问题和定义带版本的验收元数据，但不允许执行或取消项目检查、启动或取消修复、创建／合并／移除任务或恢复源码。`read-only` 进一步禁止定义验收，但仍可写入评审问题元数据。HEY 团队总监使用 `coordinate`，文档作者和评审预设使用源码 `read-only`。工具 schema 收窄可见动作，执行定义也会拒绝越界调用。

`coding_repair` 为当前工作区提供 `start`、`read`、`cancel`。启动以当前调用 Agent 为权限所有者，默认尝试一次，且不得超过部署设置的修复上限；必须关联源码仍匹配的失败检查，过期或其他工作区的 id 不是修复授权。只读及协调模式可以读取保留的修复状态，不能启动或取消修复。

<details>
<summary>策略集成</summary>

`/policy` 消费者需要 `sessionProjections`，正式发布的基础组合已提供该服务。仅 Host 可见的投影保存不同的待验证路径与当前步骤的未结算调用。相关事件的处理耗时与其输入路径及所保留状态成正比；完整重放对每个事件重复归约。读取状态不扫描日志，也不执行 I/O。版本 2 的投影缓存从保留事件重建，不改写或迁移已发布的 Session 事件。Agent 工具分派必须在进入策略前提供真实的会话日志坐标；`enforce` 拒绝未记日志的修改。策略等待必要投影完成注册，注册失败会使插件激活失败。

</details>

`/experience-recall` 插件在新用户任务获准时，自动检索当前工作区的手写台账、带出处的 SessionQuery 历史及保留的修复事实。中文请求无需插入空格即可分词，排除请求套话并保留路径和错误码原词。查询词、检索次数、匹配数与追加上下文均有界。历史片段保留 Session/事件坐标，属于不可信参考数据，不能作为指令。SessionQuery 失败会阻止准入。台账读取分别报告 `available`、`missing` 或 `unavailable`；读取失败不再被当作台账不存在，其安全提示会进入模型上下文。

`experienceSearch` 按需从已持久化的修复和检查记录派生 `repairMatches`：符合条件的失败与后续独立执行原检查的通过结果，以及运行/Session id、命令、目录、源码变化和验证序号。重复观测会折叠，相关且较新的事实优先，模型可见字段经过脱敏。这些事实只证明历史检查状态变化；`rootCause` 与 `fix` 保持 `null`，`freshness` 要求结合当前源码重新核对。它们不新写项目台账、不训练模型权重、不认证语义修复，也不创建可独立编辑的经验数据库。

`/compaction-refresh` 插件保留原生压缩，并在下一次获准的请求末尾追加当前待办、重新核验的验收状态和未解决问题。待恢复标记从会话日志重建，仅在提示获准进入模型后清除。待办所有者通过 `todoState.read` 提供回放后的状态，不缓存工具返回值。两个插件均保留已有消息前缀，并以普通用户消息事件记录追加内容。

Sweep 使用 TypeScript token 比较连续的新增代码窗口，归一化标识符名称并保留字面量。它报告供评审使用的结构相似性，不证明语义等价。

在仓库根目录运行 `pnpm run test:eval /tmp/coding-eval-report.json`，通过准备后的 `hey-headless` profile 执行缺陷修复、功能实现和重构任务。执行器管理临时 Git 仓库，在独立进程中为最终模块评分，写入报告，并拒绝失败或空的基线。它使用显式配置的测试模型凭据并消耗 API 额度。受信任的真实 API CI 作业会运行这组基线；三个小型夹具不代表生产规模的模型质量。

完成协议将完整产品交付请求路由到 HEY 团队流程，聚焦改动仍直接实现。团队模式与既有权限继续有效，技能不能虚构独立审阅者或改变工具权限。

## 证据规则

<a id="evidence"></a>

`coding_acceptance` 读取或定义关联已发现检查名称的具体验收标准。更新规格必须携带预期版本，并保留旧版本。验收项必须关联可执行检查，撰写说明不等于成功运行。

验收规范可通过 `independentVerificationOf` 指定真实实现者的 Session ID。每项必需检查必须由其他 Session 在当前源码和规范修订上执行。仍以最新执行为准：实现者再次执行、后续失败或源码变化都会阻止验收，直到符合条件的验证者重新运行。这只确认执行者独立于已声明的实现者，不证明代码评审质量，也不会识别未声明的参与者。省略该字段时保留之前的选择；显式传入空列表可清除限制。历史规范没有该字段时不限制执行者。显式提供的实现者必须是同一工作区中经过会话头校验的成员。已完成成员无须恢复运行即可登记；无关或未知的 Session ID 会被拒绝。

`coding_check` 保留实际 argv、工作目录、源码指纹、状态、退出码与有界日志。验收采用每个检查的最新执行、当前规格，以及完整且一致的执行前、执行后与当前源码指纹。后续失败、取消、超时、中断或源码变化会阻止复用旧的通过结果。持久化单调序号确定执行先后，不依赖系统时间。没有该序号的旧记录仍可读取，但必须重新检查才能用于验收；未解决问题阻塞验收。

`evidenceSnapshot` 从同一份一致观测提供保留记录、源码感知评估和历史质量指标。评估期间记录变化时最多重试三次，持续变化则报告 `evidence-changing`，不把旧通过和新失败拼在一起。每类历史视图最多展示 `resultLimit` 与 50 中的较小值，输出和诊断文本均有上限，并明确提供总数和截断状态。历史通过率不等于当前验收。

桌面交付验证以分页、只读方式展示该观测中的检查、问题、修复及任务详情。“准备修复”创建标准会话草稿供复核，不会静默发送模型请求或启动修复；页面也不把委派 worker 复用为普通对话。该观测只读取一次：检查、修复或源码发生变化后需刷新，不是持续在线的完成保证。

安装级存储在 Host 重启后保留记录，中断的执行保持中断。保留的文本改动支持比较后恢复，发现后续用户修改时拒绝覆盖。隔离任务复用现有 worktree 服务。任务提交把所选文件按字面路径解释，支持已跟踪文件的删除，并保留其他暂存改动。这些操作保持应用既有沙箱与批准策略。

自动修复从源码指纹仍完整匹配的失败检查开始。每次尝试都创建新的标准实现子会话，保留当前调用者的沙箱与批准策略；子会话停止后，由服务在记录的工作目录独立重复原始命令参数。检查清单变化时停止修复，参数经过脱敏的命令需要手动验证。旧子会话关闭后才开始下一次尝试；最终的子会话 id 指向最近一次尝试，每次检查回执仍关联对应 Session。取消会等待当前工作结算，已停止或中断的记录不会成为通过。

## 模型体验

### 原生开发工具

#### 模型看到什么

静态系统提示指导普通开发任务先检查源码和 Wiki/知识库，小修复保持小范围，并使用可执行验收。普通开发预设提供 `coding_inspect`、`coding_acceptance`、`coding_check`、`coding_repair`、`coding_review`、`coding_task` 和 `coding_restore`。工具调用及结果进入普通会话日志；桌面工程验证读取同一份记录，不依赖模型给自己打分。

#### Token 影响

工具结果包含有界证据，不整包追加源码或原始凭据。

#### KV Cache 影响

工具 schema 静态，执行结果追加到现有会话。

## 已知限制与后续工作

<a id="limits"></a>

- 指纹描述配置范围内的源码扫描，不涵盖外部数据库、远程服务或全部运行依赖。
- 经验事实是保留记录的有界历史视图，不是独立根因分析或当前验收。手写笔记仍属不可信参考资料；不提供自动事实的独立编辑/删除界面或模型权重训练。
- 文档完整性、工程检查、独立评审、用户批准和生产部署是不同事实。
- 影响分析提供文本和导入线索，不代表完整的语义依赖图。
- 覆盖 glob 由操作者在 `.hey/coding.json` 中声明；包级覆盖不做自动探测，因此未声明覆盖的检查在 changed 范围内始终运行。
- 策略跟踪会话保留的原生与 PTC 修改记录；带外文件变更只能由指纹新鲜度规则发现，策略不感知。旧检查结果若已转存且没有可读记录，会继续待验证，直到新检查通过。
- 交付页提供有上限的只读证据视图，不是完整的任务／工作树管理界面。编辑后自动附加 LSP 诊断、自动提醒任务板状态仍待实现；任务板状态没有追加进模型上下文，不等于持久任务数据丢失。
