# @deepseek-ai/dsh-uma-base

[English](README.md) | 中文

## 概述

此私有 bundle 在内核运行时上提供 UMA Host 服务。UMA Web、桌面与自动化配置显式选择它。它不选择浏览器传输，也不更改官方配置模板。其包由本地发行版提供，不是 npm 安装目标。

## 使用此包

模型根据当前任务决定是否委派或查阅资料。UMA 标准及岗位预设通过 `uma_workspace_search` 查询知识库和已复核经验，通过 `coding_inspect` 查询项目历史，通过 `uma_wiki_lookup` 查询经源文件验证的 Wiki 信息。模型调用 `design_begin` 时才准备设计资料。团队模式提供具体工作的委派能力。模型处理用户请求前不会启动队员或预加载项目参考资料。已复核经验属于历史证据，候选经验须经复核后才会被检索返回。团队模式开启时，根会话的编程验收结果还要求共享任务板已收尾；成员的独立检查不受此限制。关闭团队模式保留任务并允许单智能体验收。

共享组合将检查失败、检查恢复和部分结构化工具故障记录为本机全局经验候选。启动时恢复可用的检查记录，并按来源去重。项目集合可选择额外记录检查恢复。全局记录保留证据引用，省略命令输出和会话正文。

新建根会话默认开启团队模式。需要明确分工时，UMA 工作流程由具名成员负责共享任务。小型改动可由主助手直接实现，并安排独立设计或评审。涉及界面的工作由设计角色读取所选设计库参考并交接决策。用户可按会话切换团队模式。

团队模式开启时，用户在界面任务中明确要求设计师，标准和 PTC 会话会启动设计角色。要求单人处理、关闭团队模式或处于计划模式时跳过这次调度。其他角色与工具仍由项目总监按任务决定。

UMA Web 和桌面为 `/反馈` 选择 `./feedback` 提供方：只把明确输入的文字提交到已登录 UMA 账号来源的 `/v1/me/support`，并返回已确认的工单链接。不附加 Session 历史、附件或设备信息。`origin` 默认为 `https://studio.umayun.com`，`allowLoopbackHttp` 默认为 `false`，`requestTimeoutMs` 默认为 `15000`。结果不确定时不自动重试，应先检查工单列表。自动化 profile 保留内核的本地记录命令。

在内核模式 bundle 之后、UMA Web 或自动化层之前加载此层。发行版配置助手统一维护 bundle 顺序。现有配置补丁仍位于后续层，可配置已声明的条目。

登录并打开已导入的工作区后，可用 `/memory save <名称> <内容>`、`/memory list`、`/memory show <名称>` 和 `/memory delete <名称>` 管理记忆。用同一名称保存会替换内容。数据库位于本机 Harness 主目录的 `uma-project-memory` 下，按账号和规范工作区隔离。Agent 可以用 `uma_project_memory` 在后续会话按需读取用户保存的决定。删除后不再召回，已经显示或发给模型的内容仍可能留在过去的会话记录中。

项目记忆优先匹配完整名称，其次匹配标题和正文中的词。中英文均在本机分词，同分时按最近更新顺序返回。

WeKnora 可作为可选的只读来源。通过本地配置启用 `uma-weknora`，填写 `url`、`accountOrigin`、`accountId`、`workspaceId`、`apiKeyRef` 和明确的 `knowledgeBaseIds`。使用只对这些集合开放的读取凭据。工具仅在账号和工作区匹配并被调用时向该服务发送检索问题，返回带文档和片段标识的内容。本地知识库独立可用。全文和向量索引仍由本地知识提供方配置。

WeKnora 请求限定结果数量。相同来源的重复片段只计一次。

在 UMA Host 启动环境中设置 `UMA_KNOWLEDGE_EMBEDDING_URL` 和 `UMA_KNOWLEDGE_EMBEDDING_MODEL` 后，本地集合可以选择混合检索。端点需要凭据时再配置 `UMA_KNOWLEDGE_EMBEDDING_KEY_REF`。用本机 OpenAI 兼容向量接口可在本地生成文档和查询向量，外部端点会收到文档片段及查询。更换向量提供方后需要为现有混合集合重建索引。

UMA Web 和桌面版在经过认证的 Host 上提供 SSH 传输。终端、巡检和 SFTP 使用 Host 所有者建立的连接。操作受远端 SSH 用户的权限约束。`transferBytes` 配置单个文件的传输上限，默认 32 MiB。上传结束后将临时文件存到尚未占用的目标路径。上传失败后，通道仍可用时会清理临时文件。Linux 健康检查改编自 [Octop CVM Doctor](NOTICE.md)。用户可逐台将已连接的服务器授权给会话，默认一小时后过期，断开某台服务器会独立撤销它的授权。`uma_ssh_servers` 返回当前会话已授权的连接。`uma_ssh_run` 使用独立命令通道，多台服务器已授权时须指定连接标识，每条命令都要审批。如果 SSH 密码或私钥口令在工具输出中被回显，会自动遮盖。

## 理解实现

<details>
<summary>实现细节 — 点击展开</summary>

Host 装配向所选应用共享编码记录、本地知识、仓库 Wiki 服务与工作树创建能力。服务使用当前 Harness 主目录与工作区注册表。工作区回忆在首次检索时打开独立的派生 SQLite 历史索引；索引位于 Harness 主目录，不替代会话记录。此层没有服务依赖 `webStartup`。

可选的 Forge 和工作树工具组合包复用正在运行的 UMA 工作树服务。运行时与插件市场省略重复的服务条目。切换任一组合包时，UMA 服务和已有工作树记录仍然可用。

UMA 自有生命周期消费者在委派模型工作开始前等待串行的 `agent/created` 处理。它只接纳真实子任务：记录中的父会话已属于同一个规范化的已导入工作区。新建与恢复的子会话追加到归属列表，不改变普通对话顺序；缺失、不匹配或已删除的归属不会被自动接纳。接纳失败会回退本次新增归属，卸载时取消并等待进行中的操作。编码检查、历史召回和压缩后恢复据此取得工作区身份，其服务原有的归属校验保持有效。

共享 Host 预设为浏览器和自动化配置统一定义设计、办公、Wiki、统筹、文档编写与审阅能力。角色权限仍由各预设决定，此层不向所有角色授予全部工具。文档编写与评审成员可查询并联系协作成员，仍无派发、打断或执行权限。实现成员直接向提出问题的评审员回报修复；若修复消息只发给总监，由总监转发。

[补丁声明](cordis.patch.yml)与 `package.json` 共同维护生产依赖。所有产品包保持私有，并随本地发行版提供。

</details>

<a id="model-experience"></a>
## 模型体验

### 组合能力

#### 模型看到什么

通过所挂载的 `coding_inspect`、`coding_check`、有界 `coding_repair` 工具与 `standard` 预设间接影响模型。共享预设定义为各角色选择完整实现、可定义验收元数据的协调能力，或源码只读的证据／评审能力；共享 Host 层不向所有角色授予完整工具集；各插件包拥有其工具 schema 与上下文文本。此 bundle 不发起模型请求。

#### Token 影响

取决于所选 Agent 装配；工具和上下文的上限由对应插件包定义。

#### KV 缓存影响

bundle、预设或配置的更改可能替换请求前缀中的工具和上下文。提供商缓存的可用性与淘汰不属于此 bundle 的保证。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 工作区接纳只延续已导入的归属，不自动接纳任意目录，也不编排工作树。任务板状态提醒和九角色声明式编制仍是独立工作。
- 此层提供服务，不绑定顶层 Agent 预设。所选应用负责创建 Agent、恢复策略以及面向模型的工具位置。
