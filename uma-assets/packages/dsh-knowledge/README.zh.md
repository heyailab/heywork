# @deepseek-ai/dsh-knowledge

[English](README.md) | 中文

## 概述

将本地文档或 Markdown 笔记导入团队和项目知识库。关联已有工作区后，编码任务会自动获得相关且可引用的依据。服务保留原始快照和版本，恢复中断的解析任务，跟踪显式选定的本地来源，并排除已停用、归档或发生变化的资料。全文检索无需模型；配置向量模型后可启用混合检索。

## 使用本包

默认导出是服务类。程序化配置验证使用其静态 `Config` schema，入口的具名 `Config` 导出仅为类型。

开发经验使用同一知识库范围与启用状态，独立保存内容、不可变版本及候选、已审阅、撤回、被替代状态。修改正文会退回候选，写入和删除核对预期版本。删除移除正文与版本，但保留来源去重标记以防自动重建；已有 Session 引用不被改写。人工审阅要求解决方法、适用条件、引用和意见，不认证根因或当前源码。普通任务可召回本机全局经验库及关联且启用集合中的已审阅经验。HEY 在本机创建全局经验库，将检查失败、后续通过和部分结构化工具故障作为候选，并保留证据引用。项目集合可选择额外记录从失败到通过的检查。候选经审阅后才可召回。SQLite 升级到第 2 代并保留已有资料，旧程序拒绝读取新代数据库；回退须关闭 Host 并恢复配套备份。

桌面端与 Web 复用应用组合。全局服务管理本机目录，开发预设挂载 `@deepseek-ai/dsh-knowledge/context`。项目知识库对应一个已导入工作区；团队知识库可关联显式选定的多个工作区。团队分组只组织当前安装环境的资料，不创建员工身份，也不向其他机器发布资料。

```yaml
- id: knowledge
  name: '@deepseek-ai/dsh-knowledge'
```

数据保存在已解析的 `DSH_HOME/knowledge/v1` 下，包括 SQLite 元数据与索引、原始对象和不可变解析引用。每个知识目录只允许一个运行中的 Host；第二个 Host 会拒绝占用现有队列租约。重启会恢复中断的解析任务。独立并行 Host 应使用不同 home。

支持文本/Markdown、CSV/TSV、JSON/YAML、PDF 与 Office 文档。Office 转换复用现有 Office-to-PDF 服务；PDF 提取运行在受时间和 V8 堆约束的 Worker 中。纯图片 PDF 返回 `ocr-required`，不会将空解析标为就绪。本地来源跟踪可选，仅在应用打开期间运行。中断或失败的文件夹导入会保留已接收的文档。

[Config 源码](src/config.ts) 负责全部字节、文档、页、片段、队列、容量、超时与同步限制。默认单个原文件 20 MiB、提取文本 4 MiB、两个解析任务、每 15 秒检查来源，原始对象和索引分别限制为 2 GiB。归档内容与历史引用会保留，因此归档不会回收快照容量。

`createNoteIfAbsent` 只在所选知识库没有同名文档时接收带版本名称的 Markdown 参考资料。存储所有者以原子方式核对是否存在，覆盖用户已编辑、停用、归档及本地来源文档，因此并发导入不会替换用户资料。结果区分入队与未变化，原有 `createNote` 编辑行为不变；入队不等于已解析或就绪。

界面可将共享规范目录里的 14 篇原创双语编码指南显式导入用户选定的已有知识库。其 23 条条件化规则引用 12 组官方来源，不复制上游手册。导入不会新建或启用知识库、修改工作区关联，也不会静默重新启用文档。管理者启用并关联知识库、内容达到就绪且符合检索条件后，已有工作区检索即可向合法的编码/团队 Session 提供相关资料。

混合检索要求配置 `embeddingUrl` 和 `embeddingModel`；`embeddingKeyRef` 在每次请求时通过现有凭据服务解析。端点须提供 OpenAI 兼容的向量接口，可配置模型需要的 `queryPrefix` 与 `documentPrefix`。缺少、部分配置或失败的向量服务均明确报错，混合知识库不会静默退回词项检索。提供方或前缀变化后，已有混合文档须重新索引。

只有当前设为混合检索的知识库参与向量匹配。切换到全文检索会立即排除该库的向量，仍保留原有向量和版本供后续使用。

## 实现说明

<details>
<summary>实现细节 — 点击展开</summary>

注册表、SQLite 提供方和领域操作在本包共同演进。`types.ts` 提供浏览器安全类型，生成的 Remote 描述通过现有认证 Gateway 暴露管理操作。没有新增浏览器文件系统能力或 Electron IPC 通道；原生路径来自已有 preload 桥接，远程导入使用有界编码快照。

代码 Wiki 与文档检索共用[任务查询所有者](../../context/task-query/README.zh.md)，重启或插件替换不会丢失活动任务的查询。

父片段保留页码和行范围，较小且重叠的子片段用于精确检索。中文分词进入 FTS5/BM25；已配置向量仅在可用知识库范围内计算，再与词项候选通过倒数排名融合。结果展开为去重的父片段。资料进入任务前会重新核对来源哈希和启用状态，覆盖向量服务与文件读取等异步操作后的检查。

原始文件和引用文件先保存，再以事务切换文档版本与索引。文档代数计数防止旧解析任务覆盖新输入。关闭队列时，先取消并等待 Worker、转换、向量请求与所属操作完成，再关闭 SQLite。停用和归档的文档仍可由管理者阅读，但不进入新的检索结果。

<a id="model-experience"></a>
## 模型体验

### 工作区依据

#### 模型可见内容

`hey:workspace-knowledge` 运行时上下文提供相关知识库/文档名称、标题、页码、不可变 Markdown 路径、行范围与原文片段，范围取自实际 Session 工作区。检索文档属于参考资料，不能覆盖用户或系统指令。全部模型可见贡献均由现有持久化运行时上下文机制记录。

#### Token 影响

来源解析和全文检索不请求模型；混合索引及查询会调用已配置的向量提供方。编码任务仅接收受 `contextMaxBytes` 限制的选定依据。检索失败会明确提示不可用，不提供未经校验的事实。

#### KV Cache 影响

普通工具定义保持不变；依据更新会改变已记录的 user 角色运行时上下文快照。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- 团队分组和工作区检索范围不等于员工 SSO/RBAC 或跨设备同步。管理访问仍由 Gateway 认证控制；共享开发会话的已授权读者可看到该会话中已记录的依据。
- 不提供 OCR、音频转写、外部文档平台连接器或托管云索引。
- 向量检索使用有界精确余弦计算，不是分布式 ANN 服务；候选集过大会明确拒绝。
- 哈希校验确认来源身份，不代表验证每份文档或生成答案的语义真实性。
