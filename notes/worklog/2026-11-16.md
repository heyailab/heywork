## CI 首跑失败排查（Phase 1 补丁 apply 失败）
- 现象：5 个 hunk 全部 "patch does not apply"，报错 "while searching for:" 每行末尾多一个 `?`（即 CR），只有新建文件 hunk 通过
- 根因：windows-latest 的 core.autocrlf=true 把 patches/*.patch 在 checkout 时转成 CRLF → 上下文行尾部 \r 与 LF 上游源码不匹配（本地 LF 下 git apply --check 全绿）
- 修复：新增 .gitattributes（* text=auto eol=lf、*.patch -text、*.umadb/*.node binary）；workflow 改为 `git -C .. cat-file blob HEAD:patches/... > $RUNNER_TEMP` + CR 守卫 + apply --check + diffstat；加 concurrency 组取消被替代的构建
- 同时修掉一个真 bug：package-target 的 execute() 内部是 runPnpm()，原 `execute([process.execPath, script])` 会变成 `pnpm /path/node script.mjs`；改为 `['exec','node', script]`
- 关键上游事实（复核用）：execute=(args)=>runPnpm；executePreparation 定义在 483 行（调用点 524 合法）；buildPaths.dsh=apps/desktop/.desktop-build/targets/<target>/dsh；afterPack 校验的是源 dsh 树（extraResources to:'dsh'，非 asar，所以 asarUnpack 那条是无效但无害）；verifyDesktopRuntime 在 win32 会剥掉 executable 字段再比、sharedPackages 只强校验 dsh/host 版本
