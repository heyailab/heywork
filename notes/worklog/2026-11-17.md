## UMA Studio Windows 移植 · Phase 4（功能验收）

- **关键发现**：UMA 桌面 profile = `PROFILE_TEMPLATES.web` + `dsh-uma-base` + `dsh-uma-web`，后两层按名字挂载了 **11 个上游公开仓库 `39163dd` 未发布的一等包**（knowledge / task-query / worktree / coding-workbench / tool-repo-wiki / util-repo-wiki / client-ui-knowledge / client-ui-repo-wiki / client-ui-design-studio / api-account-controller / deepseek-account-platform）。
  - 缺了它们 Host 无法解析层条目 → profile 起不来；而 prepare 阶段 runtime smoke 跑在注入**之前**，所以构建期完全看不出来（pnpm build / electron-builder 都不校验 profile 层）。
  - 早期「12 个 uma 包 0 平台耦合、依赖全在 packages/ 内」的结论是**不完整**的，已在 PLAN.md 关键事实 #1 修正。
- **补齐方式**：`scripts/extract-mac-extras.mjs` 解析 app.asar 头（`[4][pickle][strLen][json][pad4][data]`），按依赖闭包抽取 → `uma-assets/packages/`（23 个包，26.7MB，无原生二进制）；逐包 SHA-256 与体积记入 `uma-assets/packages.extras.json`。注入清单改为**目录驱动**（不再硬编码 12）。
- **依赖池**：注入集的非 `@deepseek-ai` 运行时依赖共 9 个（zod/pdfjs-dist/picomatch/typescript/js-yaml/papaparse/yaml/ws/ssh2），全部进 `uma-assets/deps/`，注入时「树里缺失才补」。其中 `yaml` 缺失会让 `dsh-skill-uma` 解析技能 front matter 失败 → `uma_resource_read` 全废。
- **门禁**：`scripts/verify-uma-platform.mjs`（源码模式 + `--tree` 模式）
  - 22 个产品开关全部落到 269 个可挂载 id；8 启用 / 14 禁用与 Mac 原文逐字段一致（唯一允许差异 `desktopPlatform: darwin→win32`，对应 `x-client-platform: desktop-win`）
  - 层引用零悬空、40 个工具在册、客户端包必须有 `lib/client.js`、8 语种齐全、`resources.umadb` 必须在 asarUnpack
  - 注入脚本末尾自动以 `--tree` 调用它 → 在打包前（而非用户首次启动时）失败
- **`uma_wiki_lookup` 不是笔误**：由补齐的 `dsh-tool-repo-wiki` 注册（连同 10 个 `wiki_*`）；补齐前该工具根本不存在。
- **技能库**：`scripts/inspect-skill-container.mjs` → 20 个技能 / 642 目录 / 2895 文件，容器与 Mac 逐字节相同。
- **文件重命名**：`uma-assets/uma-platform.patch.yml` → `uma-platform.patch.mac.yml`（真正随包的副本由 `patches/uma-phase1.patch` 生成，且已是 win32），防止有人改错文件。
- **git**：`.gitattributes` 增加 `uma-assets/packages/** -text`、`uma-assets/deps/** -text`，否则 CRLF 归一化会让抽取件的 SHA 失真。
- 提交：`acf8abe`、`4f87f14`、`5b74fa5`、`f76f92f`（已推 `heyailab/uma-window`）。

## 范围收敛（用户 2026-11-17 明确）：只对齐功能，不做更新链路

- 用户结论：「更新功能不用管，UMA 的功能应该全在插件里」。**已用证据证实**：
  - 22 条产品开关全指向 cordis 插件 id，无一指向 Electron 代码路径；
  - Mac 主进程 50 个 IPC 通道 vs 上游 `39163dd` 42 个——**官方 ⊂ UMA（0 个官方独有）**，UMA 仅多 8 个：`operations-{list,save,remove,connect,trust}`、`tray-publish`、`product-version`、`boot-mounted`；
  - UI 也是插件：6 个客户端包声明 `dsh.client`，由 `dsh-uma-web` 层挂成 Loader entry，浏览器侧 `dsh-client-modules` 按 entry 扫 `dsh.client` 组模块图（不认层 id、不改 web shell）。
- **判定不做**：① 自动更新 + 缓存清扫（Phase 3 挂起，代码保留在 `patches/uma-phase3.patch`）；② UMA Operations（SSH 面板）——主进程 `OperationsVault`(safeStorage) + 5 个通道 + Mac 专属菜单入口（`...darwin ? [...] : []`，Windows 本无入口）；插件侧 `uma_ssh_servers/uma_ssh_run` 带 `when` 门控，无面板 = 工具不出现，不崩。
- **门禁增强**（`verify-uma-platform.mjs` 4b 节）：每个声明 `dsh.client` 的包必须被某层挂成 entry（id 或 name 命中），`dsh.client.inject` 的 21 个目标必须可解析——否则浏览器模块图缺行、UI 静默不出现、构建期零报错。现状：7 个客户端包全挂载、21 个目标全解析（19 个上游 workspace 成员在 `packages/client/*` 与 `packages/api/*`）。
- 教训：用伪造树验 `--tree` 模式两次被 SIGTERM（拷贝 412 个上游包太重）；改用「注入目标是否为 pnpm workspace 成员」来证明真树可用，伪造树路径放弃。
- 提交：`a5897df`（已推）。PLAN.md 新增「范围边界」表与 goal/acceptance 修订；`notes/phase4-acceptance.md` 新增边界判定一节 + 真机清单改为 9 步（更新项移除）。
- 用户确认下一步在 Windows 本机开发。新增 `WINDOWS-DEV.md`（提交 `2d37fa1`）：仓库构成（23 包 = lib 编译形态，官方 dsh 源不入库按 `39163dd` 自拉）、与 CI 逐步一致的完整出包流程、三种迭代方式（直接改插件 lib / 补丁后的 dsh 树改 TS / 按 cordis 模型加新包）、提交纪律（LF patch、push 前跑 verify）。补丁共触及 11 个上游文件。


## 第二轮复核：还差什么 / 哪些没分析到位（用户提问「看看还有什么要补充」）

方法：不去重读文档，而是回到 Mac 包与包源码里查**此前只有推断没有取证**的点。产出 `notes/parity-gap-review.md`（含 Mac↔Windows 单一差异矩阵）。

**已确认无误（新取证）**
- 设计工具链的三条初始化硬断言（systems / brands / knowledge 非空）全在容器内满足：507 设计系统（各带 manifest.json）、84 个 DESIGN.md 品牌、6 个知识根、20 技能。解密方式：`locate()` 从 `<skillRoot>/assets` 向上找同级 `resources.umadb`，按「相对 assets 的 POSIX 路径」查表 —— 所以 `assets/` 目录**本来就该不存在**；真建一个明文目录会让读取走磁盘分支，等于把 30MB 资产变明文。已写进 README 已知坑第 5 条。
- 23 包对 POSIX 零依赖：`sh -c`/`bash`/`chmod` 实际调用 0 处；`process.platform` 仅 `dsh-knowledge` 两处（已跳 win32 的 O_NOFOLLOW）。子进程全是 `ctx.subprocess.spawn({argv})` 无 shell，走官方 PATHEXT 解析 → 前提是 Git for Windows 在 PATH（已补进 WINDOWS-DEV 环境前置）。
- 编码工作台的 Windows 沙箱**存在**：上游 `packages/sandbox/sandbox-windows-acl`（restricted token + capability SID + 低完整性标签），`dsh-sandbox-local` 在 Windows 选它。官方自述「guarantee stays partial」（硬链接、他方 AppContainer 文件）。→ 机制有，跑通仍需真机。
- **基线漂移核对**：本机 Mac 已升 `1.0.0-beta4.20261117.1`（我们基于 beta3）。核对结果：内核仍 0.2.2-rc.3、362 包、12 UMA 包、`uma-platform.patch.yml` 逐字节相同 → 插件层无需重做。但壳层 `main.js` 1,045,645 → 1,052,262（+6,617 字节），且 Mac `dshBuildCommit=a7e944e3` ≠ pin `39163dd` → 文档里「完全一致」改为「版本号一致、commit 不同、功能面逐项核对一致」。
